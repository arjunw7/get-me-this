## Outcome

A signed-in owner with a complete profile can manually add an item to their one persistent wishlist, edit it, and permanently delete it after confirmation. Original price and currency remain exact across save, reload, display, and edit. Invalid input stays available for correction, operational failure is recoverable, and foreign or missing items expose the same data-free unavailable state. The create and edit path establishes a shared validated save boundary for later 005f extraction review.

## Scope

- Replace the 005b interim `/wishlist/items/new` page with the V18-derived manual form. Add the deferred populated-list `Add an item` affordance, an owner edit affordance, and the proposed `/wishlist/items/[itemId]/edit` route. This edit route is a 005c delivery contract accepted by the reviewed proposal, not a modification of the frozen route map. Protect only its canonical path pattern. Both pages and each create, edit, and delete Server Action call `requireCompleteProfile()` before item reads or writes; the helper performs fresh provider `auth.getUser()` and owner-profile reads. Signed-out requests go to `/auth`, incomplete profiles to `/onboarding`. Missing and foreign IDs yield the same generic unavailable response without item content or ownership hints. Protected documents and action responses are `no-store`.
- Use server-only validation and persistence under `src/wishlist/`, the existing authenticated public-key server client, and 005a owner-only RLS. Derive `owner_id` and `wishlist_id` from the fresh session and owner wishlist. Ignore all posted ownership, parent, item identity except the route-bound edit ID, image, extraction, sort, conversion, and submission-key changes outside the create contract. The form uses controlled fields and `useActionState`; a rejected save retains every raw entered field and returns field errors or one generic write-failure code.
- Draft fields are title, optional source URL, optional retailer, optional original amount with currency, optional note, and one of `really_want`, `would_love`, or `just_an_idea`. The initial desire is `would_love` (V18 `Would love`). Create persists `extraction_status = manual`, `image_url = null`, and `image_snapshot_path = null`. Edit preserves extraction and image metadata. Both use an explicitly reviewed draft plus `create` or `edit` operation at the shared validation and persistence boundary; extractor output later receives no implicit trust.
- Title follows the shared 26-code-point blank predicate and is at most 200 Unicode characters. Optional retailer is blank-to-null or 1–120 characters; note is blank-to-null or at most 2000; source URL is blank-to-null or at most 2048. Do not truncate. A nonblank URL must parse with `new URL`, have HTTP or HTTPS, a host, no credentials or control characters, no localhost/private/loopback IP literal, and only default HTTP/HTTPS ports. Classify the canonical parsed host, including alternate IPv4 and IPv4-mapped IPv6. Persist the trimmed URL only on successful validation; never fetch or follow it. Keep the raw submitted URL on error. Existing card navigation retains its HTTP(S) and `rel="noreferrer"` behavior.
- Pin the supported currency metadata to active alphabetic entries with numeric minor digits in SIX ISO 4217 List One dated 2026-09-17, excluding `N.A.` and unlisted codes. One table drives validation, exact edit prefill, and list formatting. V18 quick choices are INR, USD, GBP, EUR; supported stored alternatives stay available on edit. Parse unsigned decimal text with strings and `BigInt`, reject exponents, separators, symbols, negatives, non-finite values, excess precision, and values above signed Postgres `bigint` maximum `9223372036854775807`. Zero is valid. Empty amount stores both original columns null. Serialize minor units to PostgREST as canonical decimal text and select bigint as text; never pass through a JavaScript number. Use integer arithmetic and padding to format. Supported existing nonnegative bigint values prefill exactly. If a stored code is unsupported, show raw minor-unit text and code with an unavailable-price explanation; omit both original fields on an unrelated edit, and require explicit clear or supported replacement to change them. No approximate conversion is introduced.
- Add only a forward migration for nullable `client_submission_id uuid` on `wishlist_items`, unique by `(owner_id, client_submission_id)` while non-null, with authenticated INSERT permission and no UPDATE permission. Do not edit applied 005a migration. The form generates one UUID per new draft; Start over clears all fields to defaults, generates a new UUID, and stays on manual entry. The server validates the UUID. For a live owner/key row, compare the current normalized editable payload with the new normalized payload before calculating append position. Equal payload succeeds as a replay; changed payload returns `submission-conflict` with the entered draft retained and a route to edit the saved item or start a new draft/key. After insert uniqueness conflict, repeat owner-scoped lookup and comparison; if the row vanished, return generic unavailable. The key guarantees one surviving row per owner/key only. Hard delete removes the key, so a delayed retry may create a new row. Another owner may reuse the UUID. For a new key append at maximum finite sort position plus one, or 1 for an empty list; if addition cannot advance, return generic retry without inserting. Distinct concurrent keys may tie; list order remains `(sort_position ASC, id ASC)` until 005d rebalancing.
- Edit reads the current owner-scoped row at save time. Its application write allowlist is title, source URL, retailer, note, desire level, original amount minor, and original currency. If the original pair changes or clears, the server may additionally null all four converted columns in the same update: `converted_amount_minor`, `converted_currency`, `conversion_rate_source`, `conversion_rate_at`. If unchanged, omit all four from the update. Never accept posted converted values. Do not rewrite owner/parent ID, row ID, sort position, extraction status, image fields, or submission key. Zero updated rows are unavailable. Successful create/edit navigates to a fresh `/wishlist` server read with a short success notice.
- Edit has a separate `Delete item` control. An accessible dialog names only the current owner's item, explains permanent removal, and offers Cancel and Delete item. Cancel has no mutation. The owner-filtered delete returns the affected ID; exactly one returned owner row establishes a newly successful deletion. Zero rows, including missing, foreign, or concurrent removal, yield generic unavailable. Definite rejection before mutation leaves the item and a recoverable error. After an uncertain/lost response, keep the UI recoverable and reconcile with an owner-scoped read or retry: if absent, say no longer available without claiming this request newly deleted it; if present, allow retry. Edit after concurrent delete is unavailable.
- The photo area is a styled, noninteractive placeholder saying upload arrives later. No local preview or file picker suggests an unsaved photo persists. A new item renders the branded card placeholder after reload. Edit does not expose replacement; existing remote-image display fallback stays as in 005b. No remote image input, extraction, remote server fetch, conversion-rate lookup, Storage upload, or snapshot resolution occurs here.

## Acceptance criteria

1. Signed-out page GET and valid current-build create/edit/delete action POST redirect to `/auth`; incomplete profiles redirect to `/onboarding`; expired sessions do not mutate. Protected responses are `no-store`. The canonical edit path is protected; malformed IDs and unknown children do not reveal data. Fake action headers and empty POST checks are supplemental only.
2. The owner creates, edits, and confirms deletion with exact database before/after assertions and full-reload reads. A second user cannot see or mutate the row by page, real action, or direct authenticated RLS API. Forged ownership, parent, item identity, editable, image, conversion, sort, and extraction fields do not change unauthorized columns. The app uses no service-role client.
3. Validation tests cover the blank set, Unicode bounds including non-BMP characters, optional normalization, all desire choices, URL host/credential/control/port cases, supported and unsupported currencies, and no remote server fetch. For 0/2/3/4 minor digits, exact create, reload/list display, edit prefill, and unchanged save work near bigint maximum. Test zero, overflow, above `Number.MAX_SAFE_INTEGER`, unsupported stored currency preserve/replace/clear, rejected input retention, and no number coercion.
4. Real actions and pgTAP prove same-owner/key simultaneous creates yield one live row, distinct keys and owners stay independent, equal current payload replays, changed payload conflicts with draft retained, and conflict-then-missing is unavailable. Cover create/retry/delete interleavings and the documented possible post-delete reinsert. Replay lookup precedes append calculation; unadvanceable sort maximum rejects; ties use stable ID order and survivors keep order. Migration tests assert 18 INSERT grants, 15 UPDATE grants, no key UPDATE, RLS, and uniqueness.
5. Current-row comparison preserves all four conversion columns for unchanged original pair and clears all four on changed/removed pair; forged conversion inputs never write. Cancel sends no delete. Only one returned owner ID reports newly successful delete. Definite rejection, zero-row delete, lost response after commit, two concurrent deletes, and edit-after-delete have recoverable, data-free outcomes.
6. New no-image item shows the branded placeholder after reload; edit sends no image columns. Server-boundary instrumentation proves posted source/image URLs cause zero remote server fetches. Existing stored remote-image browser loads remain the acknowledged 005b behavior. Links use referrer protection; no title, URL, note, or private image path enters logs or analytics.
7. At 390x844 and 1440x1000, create, validation, conflict, failure, edit, confirmation, uncertain delete, and success have persistent labels, associated errors, visible focus, at least 44px targets, dialog focus/Escape/Cancel behavior, and axe results. Comparisons use matched V18 state/fixture only. Independent review records candidate hashes and exact head before approval.
8. `pnpm verify` passes or identifies an exact unavailable check. The CI database job resets local Supabase, runs `pnpm test:db`, then executes all new `E2E_LOCAL_SUPABASE` specs through explicit paths added to `scripts/e2e-local-stack.sh` in the same PR and both Playwright viewports. ## Analytics, security, and privacy

No new event containing user-entered item fields is authorized. All reads and writes use the public authenticated server client and owner-scoped RLS; the app does not use a service-role client. Action-level profile validation precedes item work, responses are non-cacheable, foreign/missing IDs share a generic state, and submitted links are never server-fetched. Local test administration may use service role only in fixture setup/teardown against a verified local Supabase URL.
