# CI blocking proof (ARJ-13 / 002e)

All runs execute the committed workflow `.github/workflows/ci.yml` on
`ubuntu-24.04`: `pnpm install --frozen-lockfile` then `pnpm verify`, with
`permissions: contents: read`, `persist-credentials: false`, a 30-minute
job timeout, and no secrets exposed to pull-request code.

1. Green run from a clean environment (implementation commit 14db50e):
   https://github.com/arjunw7/get-me-this/actions/runs/36338728797
   conclusion: success

2. Intentionally failing run (commit 0e8c9f2, trailing-whitespace
   formatting violation in README.md): the `pnpm verify` step exits 1 and
   the check fails. This proves a failing verification command turns CI
   red; it does NOT prove GitHub blocks merging, because the check is not
   yet a required status check — branch protection and rulesets return
   403 on this private repository. Until protection becomes available,
   merging is gated by explicit human review with green CI as a mandatory
   review input (temporary, documented exception).
   https://github.com/arjunw7/get-me-this/actions/runs/36338823060
   conclusion: failure ("Install and verify" step: Process completed with
   exit code 1)

3. Green run after the immediate revert (commit 9b2873a):
   https://github.com/arjunw7/get-me-this/actions/runs/36338859767
   conclusion: success

The failing commit was reverted immediately; no other content changed.
Note: run 2 was allowed to complete before the revert was pushed because
pull-request runs cancel superseded runs in progress.
